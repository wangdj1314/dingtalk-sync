## 二、原始数据格式详解

### 2.1 聊天记录 `_chat_export/{会话名}.csv`

- 编码：UTF-8 with BOM（`utf-8-sig`）
- 文件名：会话标题经 `safe_filename()` 清洗（`[<>:"/\|?*]` -> `_`）
- 增量追加：每次同步只拉取上次截止时间之后的新消息，追加到同一 CSV

| 列名 | 类型 | 说明 |
|------|------|------|
| 时间 | string | `YYYY-MM-DD HH:MM:SS`，UTC+8 |
| 发送人 | string | 显示名（如"王瑾"、"DJ Wang"） |
| 类型 | enum | `text` / `file` / `image` / `calendar` / `empty` |
| 内容 | string | 见下方各类型说明 |

**内容字段按类型的格式：**

- **text**：纯文本或富文本。可能包含：
  - `[图片消息](mediaId=@xxx&openMessageId=msgYYY)` — 内嵌图片
  - `[钉子]` / `[微笑]` 等钉钉表情标记
  - Markdown 链接 `[文字](https://...)`
  - `@某人` 提醒
  - 钉钉运动卡片（以 `lippi-health-PushRankMsgToConversation:` 开头）
  - 文件更新通知（含"我更新了 【文件名】"）
  - 会议邀请（含"主题：xxx"、"会议号：xxx"、meeting.dingtalk.com 链接）

- **file**：`[文件] 文件名.xlsx fileId: y20BglGWO23k... 注意：如需下载使用dws drive download命令下载`

- **image**：`[图片]`（旧格式，无 mediaId）

- **calendar**：`[日程]会议标题` 或含 JSON 的结构化日程

- **empty**：空消息/系统消息，前端跳过

### 2.2 已下载文件 `{会话名}/{YYYY-MM-DD}/{文件名}`

- 位于同步根目录下，以会话标题命名的文件夹
- 按消息日期分子目录
- 文件名保持原始文件名（经 safe_filename 清洗）
- 并非所有聊天中的文件都已下载，过期文件标记为 `_expired`

### 2.3 图片 `_images/{会话名}/{YYYY-MM-DD}/{hash}.jpg`

- 由 `image_manifest.json` 记录元数据
- 文件名为内容 hash（防重复）
- 格式：jpg/png/gif 等

### 2.4 日程/会议 `_calendar_export/calendar_YYYYMMDD_HHMMSS.csv`

- 每次同步生成一个新文件（时间戳命名），viewer 需合并去重
- 编码：UTF-8 with BOM

| 列名 | 说明 |
|------|------|
| id | 日程唯一 ID（Base64 编码） |
| summary | 主题 |
| start_time | ISO 8601 带时区 `2026-07-20T10:00:00+08:00` |
| end_time | 同上 |
| is_all_day | `True` / `False` |
| organizer | 组织者姓名 |
| attendee_count | 参与人数 |
| attendees | 分号分隔的姓名列表 |
| location | 地点 |
| meeting_room | 会议室 |
| status | `confirmed` / `cancelled` / `tentative` |
| free_busy | `BUSY` / `FREE` |
| online_meeting_type | `dingtalk` 等 |
| online_meeting_code | 入会码（如 `993 828 107`） |
| description | 描述（可能为空） |
| categories | 分类（如"会议"） |

### 2.5 待办 `_todo_export/todo_YYYYMMDD_HHMMSS.csv` + `todo_latest.csv`

- `todo_latest.csv` 始终是最新一次同步的副本
- 编码：UTF-8 with BOM

| 列名 | 说明 |
|------|------|
| task_id | 待办唯一 ID |
| subject | 标题 |
| status | `未完成` / `已完成` |
| priority | 数字（10=低, 20=普通, 30=紧急） |
| priority_label | `低` / `普通` / `紧急` |
| due_time | 截止时间（可能为空） |
| created_time | 创建时间（可能为空） |

### 2.6 听记/会议纪要 `_minutes_export/`

**JSON 文件**（`{标题}_{userId}.json`）— 每条听记一个文件：

```json
{
  "taskUuid": "7632756964...",
  "basic": {
    "result": {
      "title": "IT项目周例会",
      "url": "https://shanji.dingtalk.com/app/transcribes/...",
      "startTime": 1782698076000,

      "duration": 4103419
    }
  },
  "keywords": {
    "result": { "keywords": ["内部协作", "组织架构", "..."] }
  },
  "summary": {
    "result": { "fullSummary": "> **主题**: ...\n## 章节..." }
  },
  "todos": {
    "result": { "actions": ["跟进xxx", "完成yyy"] }
  }

```

**摘要 CSV**（`minutes_summary_latest.csv`）：

| 列名 | 说明 |
|------|------|
| task_uuid | 听记唯一 ID |
| title | 标题 |
| summary | 摘要文本（可能为空） |
| keywords | 关键词（可能为空） |
| file | 对应的 JSON 文件名 |

### 2.7 通讯录 `_contacts_export/`（新模块，尚未完成首次全量同步）

- 预期输出：`contacts_YYYYMMDD_HHMMSS.csv`
- 编码：UTF-8 with BOM
- 状态文件：`_sync_state/contacts_state.json`

| 列名 | 说明 |
|------|------|
| userId | 钉钉用户 ID |
| name | 姓名 |
| jobNumber | 工号 |
| title | 职位 |
| email | 邮箱 |
| mobile | 手机号 |
| departments | 所属部门（可能多个） |

## 三、索引文件（build_index.py 生成）

运行 `python build_index.py` 后在 `_viewer/` 下生成以下 JSON：

### 3.1 `conv_index.json`

```json
{
  "generatedAt": "2026-07-25T13:00:00",
  "count": 303,
  "convs": {
    "IT各组负责人群": {
      "lastTime": "2026-07-22 15:59:11",
      "preview": "@王瑾 好的，我这边再看一下选择哪些内容做PPT",
      "count": 456
    }
  }
}
```

- key = 清洗后的会话标题（与 CSV 文件名一致，去 `.csv`）
- `lastTime`：最后一条消息时间
- `preview`：最后一条消息的纯文本预览（<=60 字符）
- `count`：去重后消息总数

### 3.2 `files_index.json`

```json
{
  "generatedAt": "...",
  "count": 529,
  "files": [
    {
      "title": "IT各组负责人群",
      "date": "2026-05-21",
      "filename": "端午节值班表.xlsx",
      "path": "IT各组负责人群/2026-05-21/端午节值班表.xlsx",
      "size": 242095,
      "sizeText": "236.4 KB"
    }
  ]
}
```

- `path` 是相对于同步根目录的路径
- 前端通过 `DATA_BASE + path` 拼接访问

### 3.3 `image_index.json`

```json
{
  "generatedAt": "...",
  "count": 3800,
  "images": { "@lQLPJxC2H...": "_images/王瑾/2026-06-02/b3155d89.jpg" },
  "byKey": { "王瑾\x002026-06-02 16:08:09\x00王瑾": ["_images/..."] },
  "byOpen": { "msgOXyso/f4v9w...": "_images/..." }
}
```

三种匹配策略（优先级从高到低）：
1. `images[mediaId]` — 精确匹配
2. `byOpen[openMessageId]` — 按消息 ID 匹配
3. `byKey["会话\x00时间\x00发送人"]` — 兜底桶（按顺序取）

## 五、关键约定与注意事项

### 5.1 文件名清洗规则（sanitize）

同步引擎和前端共用同一套规则：

```python
# Python (dingtalk_sync.py / build_index.py)
re.sub(r'[<>:"/\\|?*]', '_', name).strip()
```

```javascript
// JavaScript (app.js)
name.replace(/[<>:"/\\|?*]/g, "_").trim()
```

所有会话标题到文件名/目录名的转换都走这个逻辑。Viewer 中 `sanitize()` 函数必须与同步端保持一致。

### 5.2 "我"的标识

```javascript
const SELF_NAMES = ["汪德嘉", "DJ Wang"];
```

消息气泡靠右显示。如果部署给其他人用，需要改成配置化。

### 5.3 数据刷新流程

```
1. 运行 dingtalk_sync.py（GUI 或后台） -> 拉取新数据
2. 运行 python _viewer/build_index.py -> 重建索引
3. 刷新浏览器即可看到新数据
```

建议：在同步完成后自动调用 `build_index.py`（同步引擎的 StatusWorker 结束后触发）。

### 5.4 CSV 编码

所有 CSV 均为 **UTF-8 with BOM**（`utf-8-sig`）。前端 `parseCSV()` 已处理 BOM 剥离（`charCodeAt(0) === 0xfeff`）。

### 5.5 增量同步与去重

- 聊天 CSV 是追加写入，可能有重复行（多次同步重叠区间）
- 前端通过 `时间+发送人+类型+内容` 四元组去重
- `conv_index.json` 的 `count` 是去重后的真实消息数

### 5.6 图片匹配的特殊处理

由于钉钉 API 返回的 mediaId 格式不统一（`@` 前缀 vs `$` 前缀），有归一化逻辑：

```javascript
function normMediaId(mid) {
  if (mid.startsWith("$")) mid = "@" + mid.slice(1);
  return mid;
}
```

### 5.7 部署方式

```bash
cd "D:\myfiles\钉钉同步"
python -m http.server 8777 --bind 127.0.0.1
# 浏览器访问 http://127.0.0.1:8777/_viewer/
```

- 必须通过 HTTP 服务访问（`file://` 协议下 fetch 被浏览器拦截）
- 页面会自动检测 `file://` 并显示提示
- 生产部署可放群晖 Web Station 或任意静态文件服务器
